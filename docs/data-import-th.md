# การเตรียมและนำเข้าข้อมูลสินค้า

## ข้อมูลที่สำรวจได้

- Cockpit: เตรียมรายการสินค้าอ้างอิง 10 รายการจากข้อมูลสาธารณะ ได้แก่ยาง Bridgestone 7 รุ่น แบตเตอรี่ GS ผ้าเบรก Bendix Ultra Premium และน้ำมันเครื่อง PTT ใน `server/utils/reference-products.js` โดยเก็บลิงก์แหล่งข้อมูลไว้ในแต่ละรายการ รายการนี้ **ไม่ได้ยืนยันสต็อก ราคา ขนาด หรือโปรโมชั่นที่สาขา** ไม่ใช่แค็ตตาล็อกทั้งหมดของ Cockpit
- เว็บไซต์เดิม: `data/legacy-products-page-1.csv` บันทึกรายการและ URL ภาพที่พบในหน้า Products หน้าแรก 16 รายการเป็นข้อมูลสำหรับตรวจสอบ โดยจัดเป็นแกลเลอรีฉบับร่าง ไม่ได้ตรวจสอบหรือย้ายทั้ง 101 หน้า ภาพบางรายการเป็นสื่อโปรโมชั่นเก่า ต้องตรวจสอบก่อนเผยแพร่ URL ภาพยังอ้างอิงเว็บไซต์เดิมและยังไม่ได้ดาวน์โหลดไฟล์มาจัดเก็บเอง
- ระบบ Office ที่ให้มาเปิดได้เพียงหน้าเข้าสู่ระบบ ไม่สามารถตรวจสอบสินค้าในระบบนั้นได้ ยังไม่ได้เชื่อมต่อหรือย้ายข้อมูลจาก Office
- โปรโมชันในภาพหรือเนื้อหาเก่าไม่ถือว่าเป็นโปรโมชันปัจจุบัน

## ฐานข้อมูลใหม่กับฐานข้อมูลเดิมของเว็บใหม่

`npm run db:init` สร้างตารางที่ยังไม่มีและเพิ่มข้อมูลเริ่มต้น รวมรายการอ้างอิง Cockpit โดยไม่เขียนทับรายการเดิมที่มี type และ slug เดียวกัน ถ้าเว็บใหม่มีฐานข้อมูลอยู่แล้วและต้องการนำเข้าเฉพาะรายการอ้างอิง ให้สำรองข้อมูลก่อน จากนั้น:

```sh
npm run db:import -- --reference --dry-run
npm run db:import -- --reference
npm run db:import -- --file data/legacy-products-page-1.csv --dry-run
npm run db:import -- --file data/legacy-products-page-1.csv
```

การนำเข้าปกติบันทึกเป็น **ฉบับร่าง** ให้ตรวจและเผยแพร่จากหลังบ้านทีละรายการ ไม่เขียนทับรายการเดิมที่ type และ slug ซ้ำ และรายงานจำนวนที่ข้าม หากต้องการนำเข้าข้อมูลที่ตรวจสอบแล้วเป็นสถานะเผยแพร่ สามารถเพิ่ม `--publish` ได้ โดยโปรโมชั่นต้องระบุวันเริ่มและวันสิ้นสุด ระบบจะแสดงโปรโมชั่นตามช่วงเวลาที่กำหนด การใช้ `--publish` ต้องตรวจสอบข้อมูลและสิทธิ์ใช้ภาพก่อนทุกครั้ง

## นำเข้าจาก Office

ขอให้ผู้มีสิทธิ์ส่งออกข้อมูลจาก Office เป็น CSV หรือ JSON ผ่านช่องทางที่ปลอดภัย แล้วปรับชื่อคอลัมน์ตาม `data/import-template.csv` ก่อนนำเข้า ไม่จำเป็นต้องส่งรหัสผ่านในแชต

```sh
npm run db:import -- --file /path/to/reviewed-products.csv --dry-run
npm run db:import -- --file /path/to/reviewed-products.csv
```

คอลัมน์ที่รองรับ: `type`, `slug`, `title`, `summary`, `body`, `image`, `category`, `brand`, `link`, `starts_at`, `ends_at`, `sort_order` ข้อบังคับคือ `type`, `slug` (ภาษาอังกฤษตัวเล็ก ตัวเลขและขีดกลาง) และ `title` ภาพและลิงก์ต้องเป็น HTTPS หรือ path ภายในเว็บ วันที่ใช้รูปแบบ YYYY-MM-DD ส่วน JSON ต้องเป็น array ของ object ที่ใช้ชื่อฟิลด์เดียวกัน

ระบบจะปฏิเสธคอลัมน์ที่ไม่รองรับ เช่น ราคาและจำนวนคงเหลือ เพื่อไม่ให้ข้อมูลสำคัญหายโดยไม่รู้ตัว โครงสร้างปัจจุบันยังไม่รองรับการจัดการราคา สต็อก หรือการซิงก์ Office โดยอัตโนมัติ โปรดตกลงโครงสร้างและช่องทางเชื่อมต่อก่อนพัฒนาเพิ่ม `--dry-run` ตรวจรูปแบบไฟล์โดยไม่เชื่อมฐานข้อมูล จึงยังไม่ตรวจรายการที่ซ้ำกับฐานข้อมูลจริง

## ก่อนเปิดบริการจริง

1. ยืนยันรายการสินค้าและบริการ ราคา สต็อก เงื่อนไขสาขา และโปรโมชั่นที่ยังมีผล
2. ตรวจสอบสิทธิ์และความถูกต้องของภาพ พร้อมคัดลอกภาพที่อนุมัติไปยังพื้นที่จัดเก็บที่สำรองได้
3. เชื่อมต่อและทดสอบ MariaDB การนำเข้า หลังบ้าน การสำรองและกู้คืนบนสภาพแวดล้อมจริง
4. ตรวจสอบข้อมูลบริษัท เวลาเปิด เบอร์ติดต่อ นโยบายความเป็นส่วนตัว และการติดตั้งบนโฮสติ้ง
