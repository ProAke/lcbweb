# แผนเว็บไซต์แหลมฉบังอินเตอร์ออโต้ไทร์

สถานะ: **ร่างเพื่อพิจารณาและยืนยันก่อนพัฒนา**

## 1. เป้าหมายและขอบเขตที่ตกลงเบื้องต้น

- พัฒนาเว็บไซต์ใหม่ของบริษัท แหลมฉบังอินเตอร์ออโต้ไทร์ จำกัด ด้วย Nuxt.js และฐานข้อมูล MariaDB ใหม่ พร้อมระบบหลังบ้าน
- รุ่นแรกใช้ภาษาไทย และเป็นเว็บไซต์แสดงสินค้าและบริการ ให้ลูกค้าติดต่อร้าน ไม่รวมตะกร้า สั่งซื้อ หรือชำระเงินออนไลน์ตามขอบเขตที่ตกลงไว้
- อ้างอิงแบบหน้าแรกจากภาพ Figma ที่ได้รับ และขยายรูปแบบไปยังหน้าอื่นโดยศึกษาเว็บไซต์ Cockpit เป็นหลัก
- คัดเลือกภาพและข้อมูลจาก Cockpit มาปรับใช้ด้วยมือ ตามที่ผู้ว่าจ้างแจ้งว่าได้รับอนุญาต และตรวจสอบความเหมาะสมกับสาขาก่อนเผยแพร่ ไม่ซิงก์อัตโนมัติ
- สำรวจและย้ายข้อมูลจากเว็บไซต์เดิมทั้งหมดเท่าที่เข้าถึงได้ โดยต้องตรวจสอบไฟล์และฐานข้อมูลต้นฉบับก่อนรับรองความครบถ้วน การย้ายข้อมูลไม่ได้หมายความว่าต้องเผยแพร่เนื้อหาเก่าทั้งหมดทันที
- มีโฮสติ้งอยู่แล้ว แต่ยังต้องตรวจสอบว่ารองรับการติดตั้ง Nuxt และ MariaDB หรือไม่

## 2. แนวทางภาพและประสบการณ์ใช้งาน

จากภาพที่ได้รับ หน้าแรกมีหัวเว็บสีดำ เมนูสีเหลือง โลโก้บริษัทและ Cockpit แบนเนอร์เต็มความกว้าง การ์ดรูปภาพมุมมน พื้นหลังขาว และส่วนท้ายสีดำ/เทาเข้ม จึงเสนอใช้ **ดำ–เหลือง–ขาว** เป็นหลัก และใช้สีจากภาพโปรโมชั่นเป็นสีประกอบ ไม่ใช่โทนแดง–ดำที่เคยเสนอไว้ก่อนเห็นแบบจริง

ตัวอักษรไทยควรอ่านง่ายและใกล้เคียงแบบ โดยชื่อฟอนต์จริง ขนาด สี และระยะห่างต้องตรวจจาก Figma หรือไฟล์สไตล์เพิ่มเติม ภาพที่ได้รับเป็นตัวอย่างหน้าจอเดสก์ท็อปเท่านั้น จึงต้องออกแบบมือถือให้สอดคล้องกัน หรือปรับตามแบบมือถือหากมีเพิ่มเติม

ภาพตัวอย่างมีโปรโมชั่นที่ระบุช่วงเวลาในอดีต ใช้เป็นข้อมูลอ้างอิงการจัดวางเท่านั้น ไม่ถือว่าเป็นโปรโมชั่นปัจจุบัน

## 3. โครงสร้างเว็บไซต์ที่เสนอ

| หน้า | เนื้อหาและการทำงานที่เสนอ |
|---|---|
| หน้าแรก `/` | หัวเว็บและเมนู แบนเนอร์หลัก สตอรี่/โปรโมชัน ส่วน TirePoint+ หมวดสินค้า การ์ดโปรโมชัน ข่าว/วิดีโอ แบรนด์ และส่วนท้าย ตามภาพที่ได้รับ |
| โปรโมชั่น `/promotions` | รายการโปรโมชันปัจจุบัน พร้อมรูป ชื่อ หมวด วันที่ และทางเข้าหน้ารายละเอียด |
| รายละเอียดโปรโมชั่น `/promotions/[slug]` | ภาพ รายละเอียด สินค้าหรือบริการที่เกี่ยวข้อง ระยะเวลา เงื่อนไข และช่องทางติดต่อร้าน |
| สินค้า `/products` | หมวดสินค้าและรายการสินค้า ค้นหาและกรองตามหมวด/แบรนด์; หมวดเบื้องต้นคือยาง แบตเตอรี่ ผ้าเบรก น้ำมันและสารเหลว รวมโช้คอัพหากร้านยืนยัน |
| รายละเอียดสินค้า `/products/[slug]` | รูป ชื่อ แบรนด์ รุ่น คุณสมบัติ ขนาด/สเปกตามหมวด และปุ่มสอบถามสินค้า; การแสดงราคาต้องรอยืนยัน |
| บริการ `/services` | รายการบริการพร้อมภาพและคำอธิบาย เช่น ยาง ตั้งศูนย์ถ่วงล้อ ช่วงล่าง เบรก คลัตช์ และน้ำมันเครื่อง โดยให้ร้านยืนยันรายการจริง |
| รายละเอียดบริการ `/services/[slug]` | รายละเอียดบริการ ขั้นตอนหรือคำแนะนำ รูป และปุ่มติดต่อสอบถาม |
| รอบรู้ดูแลรถ `/articles` | รวมข่าว กิจกรรม บทความ คำแนะนำ รีวิว และวิดีโอ แยกหมวดและค้นหาได้ |
| รายละเอียดบทความ `/articles/[slug]` | รูปหรือวิดีโอ ชื่อ วันที่ เนื้อหา และบทความที่เกี่ยวข้อง |
| เกี่ยวกับเรา `/about` | ประวัติบริษัท วิสัยทัศน์ ภาพศูนย์บริการ แบรนด์ และจุดเด่น โดยอ้างอิงเว็บเดิมและปรับข้อความตามที่บริษัทตรวจสอบ |
| แกลเลอรี `/gallery` | ภาพศูนย์บริการ ผลงานและกิจกรรม พร้อมหมวดหมู่และการเปิดภาพขนาดใหญ่ |
| ติดต่อเรา `/contact` | ที่อยู่ โทร อีเมล เวลาเปิดทำการ ลิงก์แผนที่และโซเชียล; ฟอร์มติดต่อรอยืนยัน |
| นโยบายและเงื่อนไข | หน้านโยบายความเป็นส่วนตัวและเงื่อนไขการใช้งาน โดยใช้ข้อความที่บริษัทอนุมัติ |

เส้นทางข้างต้นเป็นข้อเสนอ ไม่ใช่ URL ที่สรุปแล้ว โดยหน้าอื่นนอกจากหน้าแรกเป็นแนวทางขยายจากภาพและข้อมูลอ้างอิง ไม่ใช่แบบ Figma ที่ตรวจพบแล้ว

### ข้อควรตัดสินใจจากภาพตัวอย่าง

- ข้อความ “ช้อปสินค้า ออนไลน์” อาจทำให้เข้าใจว่าซื้อและชำระเงินบนเว็บได้ เสนอเปลี่ยนเป็น “สินค้าแนะนำ” หรือ “เลือกชมสินค้า” ในรุ่นแรก
- ภาพมี “เข้าสู่ระบบ / ลงทะเบียน TirePoint+” แต่ยังไม่มีขอบเขตระบบสมาชิก เสนอให้รอการยืนยันว่าจะลิงก์ไปบริการภายนอกอย่างเป็นทางการ แสดงเฉพาะข้อมูล หรือไม่แสดงก่อน ทั้งนี้ไม่ควรสร้างระบบสะสมคะแนนเองหรืออ้างว่าเชื่อมต่อได้โดยยังไม่ตรวจสอบ
- ในภาพส่วนข่าวมีพื้นที่วิดีโอเป็นกล่องตัวอย่าง เสนอรองรับลิงก์วิดีโอและภาพปก โดยพฤติกรรมการเล่นจริงต้องตกลง
- เบอร์โทรในหัวภาพลงท้าย `-4` แต่ส่วนท้ายและเว็บเดิมลงท้าย `-3` ต้องให้บริษัทยืนยันก่อนใช้งาน

## 4. ระบบจัดการหลังบ้านที่เสนอ

- **ภาพรวม:** สรุปเนื้อหาที่เผยแพร่/ฉบับร่าง โปรโมชั่นที่ใกล้หมดอายุ และทางลัดจัดการข้อมูล
- **หน้าแรก:** จัดการแบนเนอร์ ภาพ ลิงก์ ลำดับการแสดง การ์ดสตอรี่ หมวดสินค้า ส่วนวิดีโอและแบรนด์
- **สินค้าและแบรนด์:** เพิ่ม แก้ไข จัดหมวด ใส่รูปและสเปก ตั้งค่าสถานะ พร้อมข้อมูลราคาหากตกลงให้แสดง
- **บริการ โปรโมชั่น บทความ และแกลเลอรี:** เพิ่ม แก้ไข จัดหมวดและรูป ตั้งสถานะฉบับร่าง/เผยแพร่; โปรโมชั่นกำหนดวันเริ่ม–สิ้นสุดและเงื่อนไขได้
- **ข้อมูลบริษัท:** แก้ไขเนื้อหาเกี่ยวกับเรา ข้อมูลติดต่อ แผนที่ ลิงก์โซเชียล และนโยบายที่บริษัทอนุมัติ
- **คลังสื่อ:** อัปโหลดภาพ จัดการชื่อ/คำอธิบาย ตรวจชนิดและขนาดไฟล์ พร้อมสำรองไฟล์สื่อ
- **ผู้ใช้งาน:** ล็อกอินและกำหนดสิทธิ์ ตัวอย่างคือผู้ดูแลระบบจัดการผู้ใช้และเนื้อหาทั้งหมด ส่วนผู้ดูแลเนื้อหาแก้ไขเนื้อหาได้แต่จัดการผู้ใช้ไม่ได้ ทั้งสองบทบาทรอการยืนยัน
- **ความปลอดภัย:** จัดเก็บรหัสผ่านแบบแฮช ควบคุมสิทธิ์ทุก API จำกัดการพยายามล็อกอิน ตรวจสอบข้อมูลและไฟล์อัปโหลด บันทึกการเปลี่ยนแปลงที่สำคัญ และกำหนดแผนสำรอง/กู้คืน

## 5. สถาปัตยกรรมเบื้องต้น

- **หน้าบ้านและหลังบ้าน:** Nuxt.js รองรับมือถือและ SEO เช่น title, description, URL อ่านง่าย, sitemap และภาพประกอบการแชร์
- **ส่วนประมวลผล:** Nuxt server routes/API ตรวจสอบตัวตนและสิทธิ์ฝั่งเซิร์ฟเวอร์
- **ข้อมูล:** MariaDB ใหม่ ออกแบบตารางสำหรับผู้ใช้/สิทธิ์ สื่อ แบรนด์ หมวดสินค้า สินค้า บริการ โปรโมชั่น บทความ แกลเลอรี และการตั้งค่าเว็บไซต์ โดยรายละเอียดขึ้นอยู่กับข้อมูลจริงและการยืนยันขอบเขต
- **สื่อ:** จัดเก็บบนเซิร์ฟเวอร์หรือพื้นที่เก็บไฟล์ที่มีการสำรองข้อมูล โดยเลือกตามโฮสติ้ง
- **เผยแพร่:** ตั้งค่าสภาพแวดล้อมทดสอบแยกจากระบบจริง และเก็บข้อมูลเชื่อมต่อในตัวแปรแวดล้อม ไม่เก็บรหัสผ่านไว้ในซอร์สโค้ด

## 6. แนวทางสำรวจและย้ายข้อมูล

1. สำรวจรายการหน้าที่มีอยู่ ข้อมูลสินค้า รูป สไลด์ แบรนด์ แกลเลอรี และ URL เดิม รวมทั้งข้อมูลที่อยู่ในฐานข้อมูลและไฟล์หากเข้าถึงได้
2. สำรองต้นฉบับก่อนเริ่ม และทำรายการเทียบข้อมูลเก่า–ใหม่ พร้อมรายงานข้อมูลที่ขาด ใช้ไม่ได้ หรือซ้ำ
3. นำเข้าไปยังระบบใหม่โดยคงเนื้อหาเก่าไว้ตรวจสอบ พร้อมแยกเนื้อหาที่หมดอายุหรือไม่ตรงกับบริการปัจจุบันเป็นฉบับร่าง/คลังเก็บ ไม่เผยแพร่อัตโนมัติ
4. ให้บริษัทตรวจเนื้อหา รูปภาพ ราคาและเงื่อนไขก่อนเผยแพร่ และตรวจแผนเปลี่ยนเส้นทาง URL เดิมที่สำคัญไปหน้าใหม่
5. ทดสอบจำนวนรายการ รูป และลิงก์ เทียบกับรายการสำรวจ พร้อมทำรายงานสิ่งที่ย้ายไม่ได้

เว็บเดิมมีหน้าแกลเลอรีหลายหน้า จึงต้องสำรวจครบทุกหน้าและข้อมูลต้นทางก่อนประเมินจำนวนและเวลา อย่าสรุปความครบถ้วนจากการดูหน้าแรกเพียงหน้าเดียว

## 7. ลำดับการทำงานและจุดตรวจรับ

1. **ยืนยันขอบเขต** — ตรวจผังหน้า ฟังก์ชัน สิทธิ์ รูปแบบมือถือ แหล่งข้อมูล และสิ่งที่ยังไม่รวม
2. **ออกแบบรายละเอียดหน้าอื่น** — ทำแนวทางหน้าในให้สอดคล้องหน้าแรกและ Cockpit แล้วให้ผู้ว่าจ้างตรวจ ก่อนพัฒนาเต็มระบบ
3. **สร้างระบบหลัก** — พัฒนา Nuxt, MariaDB, ส่วนล็อกอิน/สิทธิ์ และระบบจัดการเนื้อหา
4. **พัฒนาหน้าบ้านและย้ายข้อมูล** — นำเข้าข้อมูลตามรายการที่สำรวจ โดยแยกเนื้อหาที่รอตรวจออกจากเนื้อหาที่เผยแพร่
5. **ทดสอบและตรวจรับ** — ตรวจบนมือถือ/เดสก์ท็อป เมนู ค้นหา ลิงก์ติดต่อ สิทธิ์หลังบ้าน การจัดการเนื้อหา โปรโมชั่นหมดอายุ และการกู้คืนข้อมูล
6. **ติดตั้งจริง** — ตรวจความพร้อมโฮสติ้ง สำรองระบบเดิมและวางแผนย้อนกลับก่อนเปลี่ยนเว็บไซต์

## 8. คำถามที่ต้องยืนยัน

1. รุ่นแรกต้องการหน้าและระบบตามข้อ 3–4 หรือมีรายการต้องเพิ่ม/ตัด?
2. TirePoint+ ให้ลิงก์ไปเว็บทางการ แสดงข้อมูลอย่างเดียว หรือซ่อนก่อน? หากเชื่อมระบบสมาชิกจริง ต้องมีเอกสาร/ช่องทางเชื่อมต่ออย่างเป็นทางการ
3. แสดงราคาสินค้าหรือให้ติดต่อสอบถามทั้งหมด? ต้องการฟอร์มติดต่อหรือใช้โทร/LINE/โซเชียลเท่านั้น?
4. ขอยืนยันหมวดสินค้าและบริการที่มีจริง โดยเฉพาะรถบรรทุก/รถบัสและโช้คอัพ
5. สิทธิ์หลังบ้านสองระดับตามข้อเสนอเพียงพอหรือไม่?
6. เบอร์โทร ช่องทาง LINE โซเชียล เวลาเปิดทำการ และแผนที่ที่ถูกต้องคืออะไร?
7. มีแบบหน้าอื่น/มือถือ โลโก้ไฟล์ต้นฉบับ และไฟล์ภาพที่อนุญาตให้ใช้หรือไม่?
8. เข้าถึงไฟล์และฐานข้อมูลเว็บไซต์เก่าได้หรือไม่ และโฮสติ้งรองรับ Node.js/Nuxt และ MariaDB อย่างไร? ไม่ต้องส่งรหัสผ่านในแชต
